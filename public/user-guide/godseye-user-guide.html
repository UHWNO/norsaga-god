User Guide / Overview
Introduction

A live view of the world through connected data.

God's Eye is an interactive global situational-awareness platform that brings live, near-real-time and contextual information from multiple data sources into a single 3D environment.

The principle: Do not begin with the data. Begin with the question.

One operational workspace

Instead of moving between separate tracking systems, weather tools and information sources, God's Eye lets you build one operational view around the situation you are investigating.

Use only what matters

The platform is not intended to display every available layer at once. Activate only the information needed to answer the current question.

  • Vessels
    Maritime activity and available vessel information.
  • Aircraft
    Aviation activity within the selected area.
  • Satellites
    Tracked space objects and orbital context.
  • Weather
    Environmental context for operational activity.
  • Natural events
    Earthquakes, fires and other detected events.
  • Cameras
    Available public visual sources.
  • Infrastructure
    Geographic and operational reference layers.
  • Scenes
    Reusable saved operational views.
Quick Start

From question to operational view

Most work in God's Eye follows the same five-step pattern. Start with the question, build only the context you need, and save useful configurations for later.

1

Start with the question

Decide what you are trying to understand: a vessel, aircraft, location, incident or wider area.

2

Choose the location

Navigate manually or use Search to move directly to the relevant place or supported object.

3

Turn on relevant layers

Activate only the information that adds useful context to the current task.

4

Investigate

Select objects, review available details, move the camera and add context where required.

5

Save the view

If the configuration is useful, save it as a Scene so you can return to it without rebuilding it.

Question→Location→Layers→Investigate→Save

Interface

Navigate, search and inspect

The 3D globe is the main workspace. Use the camera to move from global context to local detail, then select supported objects to inspect the information currently available for them.

Navigate the globe

Rotate the Earth, zoom from global to local, change camera angle and move between regions.

Search

Use Search to locate supported places, geographic positions, vessels, aircraft, infrastructure and other indexed objects.

Select objects

Choose visible objects to open the information currently available for them instead of keeping every detail permanently on screen.

Visual modes

Change the map or visual environment to suit the task. These settings can also become part of a saved Scene.

Working pattern: See → Select → Investigate → Add context.

Data Layers

Add context only when it helps

Each layer adds a different perspective. Combine them when the relationship between datasets helps answer the operational question.

Vessels

View maritime activity and, where provided, details such as name, position, course, speed, heading, type, identification and voyage information.

Aircraft

View aviation activity over an area and combine it with maritime or geographic context.

Satellites & space

Visualise supported satellites or space objects and understand their relationship to a selected area on Earth.

Weather

Add environmental context to vessels, aircraft, ports, coastal areas and incidents.

Earthquakes & fires

Display available natural-event and hazard information together with nearby operational context.

Cameras

Use available public camera sources to add visual information from selected locations.

Infrastructure

Add geographic and operational reference information such as ports, transport or other supported infrastructure.

Annotations

Add areas of interest, incident positions, reference points and notes to the working picture.

A missing object does not necessarily mean the object is absent. It may mean the relevant source does not currently provide data for that object or area.

Scenes & Sharing

Save the operational picture

Scenes are one of the central features of God's Eye. A Scene stores the important elements of a working view so the same configuration can be reopened quickly.

A Scene can preserve

  • Geographic location
  • Camera position
  • Zoom level and viewing angle
  • Active data layers
  • Visual settings
  • Relevant configuration

Sharing a view

Where the application state is represented in the link, a configured view can be shared so another user opens God's Eye at the intended location and perspective with the relevant configuration.

AI Control

Use natural language to reduce interface complexity

Where enabled, AI control provides another way to navigate and configure God's Eye. The user describes the intended task, and the platform helps translate that request into an appropriate view or action.

What AI helps with

Navigation, finding supported locations or objects, configuring relevant views and reducing the number of manual interface steps.

What AI does not change

AI does not alter the underlying source information. It is an interaction layer over the data and functions available in the platform.

The useful mental model is simple: describe what you want to see, rather than thinking first about which controls you must operate.

Data & Sources

Understand timing, coverage and availability

God's Eye combines information originating from different external systems. Those systems can have different update frequencies, geographic coverage, accuracy, restrictions and temporary outages.

LiveInformation updated continuously or with very low latency.
Near real-timeInformation updated frequently, with some delay between the original event and its appearance in God's Eye.
DelayedInformation where the source intentionally or technically introduces a longer delay.
StaticReference information that does not require continuous updating.
The presence of an object on screen should not automatically be interpreted as proof of its exact position at that specific second. When timing matters, check the available source timestamp and status.

Best Practices

More data is not always better

One of the easiest mistakes in a situational-awareness platform is activating every available layer. More information can create noise instead of clarity.

Use the minimum number of layers required for the task

Question→Location→Relevant layers→Objects→Context

Add another layer only when it helps answer the question.

Example workflow: Norwegian Sea

1

Move to the area

Navigate to the Norwegian Sea.

2

Add vessels

Activate Vessels to establish the basic maritime picture.

3

Add weather

View maritime activity in environmental context.

4

Select what matters

Choose a relevant vessel and review the information available.

5

Add context if needed

Enable Aircraft, Infrastructure, Satellites or another layer only if it helps.

6

Save the result

Adjust the camera and save the configuration as a Scene for later use.

God's Eye principle: Start with the question. Choose the location. Activate the relevant information. Investigate what matters. Add context when necessary. Save the result when the view is worth returning to.
